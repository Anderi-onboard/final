## 【说明】为什么这两批先做,而且为什么它们不能靠提示词补

这两批是**查表**,不是判断。

- SOP-3 回答「这条生克到底算不算数」—— 元神休囚化退神,它那个「生」是**不成立**的。
- SOP-5 回答「什么时候应验」—— 旬空之爻应在出空或冲空之日。

让模型每卦自己推一遍这两件事,就是上线那副断错的盘的死法:它每次推的结果不一样,
而盘面事实必须每次都一样。**能得出 ≠ 每次都得出同一个。**

所以这两批的产物**要进代码,不进提示词** —— 打标出来的 `机器值` 由程序求值,
`原文` 才发给模型。

## 【说明】为什么每条只有三格

`functions/_lib/doctrine/exam.js` 的头注写着这条,再抄一遍判据:

> 要不要多加一格,判据是:**模型拿着原文能不能自己得出它。能就不写。**

第一版每条写十二格(场景、门槛、现实钩子、不许说……),九格是手写模型本来就会做的事。
所以这两批只有:

| 格 | 谁用 | 能不能重新生成 |
|---|---|---|
| `id` | 程序寻址 | 能(但一旦发出去就不许改) |
| `原文` | 模型讲话 | **不能** —— 这一格是这次打标唯一不可再生的东西 |
| `机器值` | 程序求值 | 能,但必须每次一样,所以写死 |

## 【说明】最要紧的一条:字段名不许发明

`机器值` 里出现的每一个字段名,必须是引擎**今天已经算出来的**那些。
引擎算不出来的,写 `"缺": "……"` 说明差什么,**不要编一个名字**。

这条是整个任务的重点:我要的不只是转录,还有一张「哪些条今天就能接上、哪些条还得先写引擎」的名单。
编出来的字段名会让第二类伪装成第一类,而它跑起来永远是 `undefined`,**不报错,只是永远不成立**。

## id 怎么编

SOP-3.<组>.<序>

组名只有这六个,不许新增:
  元神.能生     元神五能生      序 1-5
  元神.不能生   元神六不能生    序 1-6
  忌神.能克     忌神五能克      序 1-5
  忌神.不能克   忌神七不能克    序 1-7
  进神           四进            序 1-4
  退神           四退            序 1-4

三墓另编:SOP-3.三墓.日墓 / .动墓 / .化墓 / .冲开 / .破墓

## 原文这一格

**逐字转录,不要改写、不要润色、不要补主语、不要翻译成白话。**
原书说「元神旺相,或临日月,或日月动爻生扶者」,就写这句,不要写成
「元神处于旺相状态时」。

这一格会原样发给大模型,让它拿古文的原话去讲解。改写等于把断法换成
你对断法的转述,而转述没有出处。

原文如果有夹注、有例子,一并收进来,用「。」分句,不要分成多个条目。

## 机器值这一格

机器值描述:**在什么条件下,这条断法成立**。结构:

{
  "主体": "元神" | "忌神" | "动爻" | "变爻" | "用神",
  "判":   "能生" | "不能生" | "能克" | "不能克" | "进神" | "退神" | "入墓" | "出墓",
  "条件": [ <条件对象>, ... ],     // 数组内是「且」的关系
  "或":   [ [<条件>...], [...] ]   // 可选。数组之间是「或」的关系,组内仍是「且」
}

### 条件对象只有四种写法

1. 爻自身状态
   { "字段": "<状态字段名>", "值": true }
   { "字段": "旺衰", "值": ["旺","相"] }          // 值是数组时表示「取其一即可」

2. 爻与时钟(日/月/太岁/时辰)的关系
   { "对": "日辰"|"月建"|"太岁"|"时辰", "关系": "<时钟关系名>" }

3. 爻与另一爻的关系
   { "对爻": "元神"|"忌神"|"用神"|"世爻"|"应爻"|"任一动爻", "关系": "<爻爻关系名>" }

4. 变爻回头作用
   { "变爻": "<变爻关系名>" }

### 允许用的字段名(引擎今天已经算出来的,只有这些)

状态字段(第 1 种写法用):
  旬空 真空 假空 月破 真破 假破 暗动 日破 日墓 月墓
  动化入墓 动化空 世爻 应爻 发动
  旺衰      —— 取值只有五个:旺 相 休 囚 死

时钟关系名(第 2 种写法用):
  临 冲 合 害 刑 受生 受克 生出 克出 比和 入墓

爻爻关系名(第 3 种写法用):
  生 克 比和 冲 合 害 刑

变爻关系名(第 4 种写法用):
  回头生 回头克 回头冲 回头合 化进神 化退神 化入墓 化空 化绝 化鬼

### 表达不了的时候写「缺」,不要发明字段

条件里需要一个上面没有的东西时,**不要编字段名**,把这条的机器值写成:

  { "主体": "...", "判": "...", "缺": "引擎没有『长生十二宫』,判不了「化长生」" }

「缺」这一格比机器值本身还重要 —— 它是我要的第二份产出:
哪些条今天就能接上,哪些条得先给引擎加东西。

编一个不存在的字段名,程序跑起来会拿到 undefined,**不报错、只是这条永远不成立**。
那比缺一条更糟,因为它看起来是做完了的。

## 应:这一格是 B 独有的

应期是「等到哪一个干支」。所以每个应期对象说的是:**相对这个爻的什么支**。

{ "取": "<取法>", "自": "本爻" | "变爻" | "墓库" | "合神" }

取法只有这九个,不许新增:

  值      逢本爻的地支(申爻应在申)
  冲      逢冲本爻的地支(申爻应在寅)
  合      逢合本爻的地支(申爻应在巳)
  填实    空爻/破爻逢本支填实 —— 和「值」的算法一样,但原书是两个词,分开记
  出空    出本旬(不是一个支,是一段)
  长生    本爻五行的长生位
  帝旺    本爻五行的帝旺位
  墓      本爻五行的墓库支
  冲墓    冲开墓库的那个支(墓库支的对冲)

举例:
  「旬空之爻,应在出空之日,或日辰冲空之日」
  → "应": [ { "取": "出空", "自": "本爻" }, { "取": "冲", "自": "本爻" } ]

  「化进神者,应在变爻值日或合日」
  → "应": [ { "取": "值", "自": "变爻" }, { "取": "合", "自": "变爻" } ]

## 尺度:原书说了才写,没说写「未言」

原书有时说「应在某日」,有时只说「逢冲即应」而不说是日是月。

**不要替它填。** 没说就写 "未言"。

理由:尺度实际由旺衰缓急定(急则应日、缓则应月),那是另一条断法,
不是这条。你在这里填一个,就是把两条断法合成了一条,而且是悄悄合的。

## 表达不了的时候写「缺」

和批次 A 同一条:需要引擎没有的东西时,写

  { "缺": "引擎没有长生十二宫表,算不出长生位" }

不要发明字段名。「缺」是我要的第二份产出。

⚠️ 特别提醒:上面「取法」里的 长生 / 帝旺 两个,引擎**今天大概率没有**。
照写取法就行(取法表是我定的,不是你编的),但如果原文还要求别的东西,那才写「缺」。
