# 四节点 · ComfyUI

一站一个节点,连线就是管线。**改一站的提示词,只有那一站和它下游重跑。**

```
端点 ┐
问题 ┼─→ M1 读问题 ─→ 起卦(无模型) ─┬─→ M2 选库 ─→ M3 取证 ─→ M4 解读
     │        db=                    │      ↑          ↑           ↑
     └────────────────────────────────┴──────┴──────────┴───────────┘
```

## 装法一:打一个自带依赖的包(不需要这个仓库)

```bash
npm run pack      # → dist/bournewise-comfy-<构建标签>.zip,约 116KB
```

解开,把 `bournewise-comfy` 整个文件夹放进 `ComfyUI/custom_nodes/`,完事。
包里带着引擎、提示词、RAG、两张图和假端点 —— **没有 npm 依赖,没有 Python 依赖**,
只要 node ≥18 在 PATH 上。

⭐ **它是构建产物,不是分叉。** `repo/` 底下每个文件都和仓库里**字节完全一致**
(为此包把仓库的目录结构原样放进 `repo/`,于是每一行 import 和 `parents[2]`
都自动落对,一行都不用改写);文件清单是**顺着 import 算出来的**,不是写死的;
`MANIFEST.json` 记着源提交和每个文件的 sha256。
`tests/comfy-pack.mjs` 把包铺到系统临时目录里**真跑一次** —— 少带一个文件时
`pack.mjs` 和 `nodes.py` 都一声不吭,**只有用户那台机器会炸**,所以这件事
必须跑过才算数。

## 装法二:软链(在仓库里开发时用)

**软链,不要复制:**

```bash
ln -s /你的路径/final/tools/comfy ~/ComfyUI/custom_nodes/bournewise
```

复制一份进 `custom_nodes` 就是又一张要同步的名单:盘和提示词还在仓库里改,
Comfy 上跑的是你复制过去的那一天的版本 —— **两边都不会报错。**
真要复制,就给 ComfyUI 设 `BOURNEWISE_ROOT=/你的路径/final`。

要 **node ≥ 18** 在 PATH 上(盘和提示词都在 JS 那边)。ComfyUI 看不见 node 的话设
`BW_NODE_BIN=/绝对路径/node`。除此之外**没有任何 Python 依赖** —— 只用标准库。

起 ComfyUI,把 `workflows/bournewise-4node.json` 拖进画布,填三样:
端点地址、每一站的模型名、问题。

## 为什么是 Comfy 而不是 `tools/lab/run.mjs`

`run.mjs` 的核心用法是**钉住上游**:

```bash
node tools/lab/run.mjs --only m3 --from runs/最新那个.json
```

不钉住,你分不清"这次答得不一样"是因为提示词改了,还是因为 M1 这次答得不一样。
**Comfy 的执行缓存天生在做这件事** —— 改 `prompts.js` 里 M3 那一段、存盘、再跑,
只有 M3 和它下游重跑,M1/M2 和盘原封不动。**不需要记得钉,也就不会忘了钉。**

⭐ 每一站的提示词**分别取哈希**(`IS_CHANGED`),所以改 M4 不牵动 M1。
哈希算的是:这一站在 `prompts.js` 里的那一段 + `fill.js`(填槽和 VOICE)+
M2/M3 再加上检索表。**切不出那一段时回落到整份文件** —— 宁可多重跑几站,
也不能少重跑一站:那会让你对着**上一版提示词的答案**调这一版。

## 节点

| | 做什么 | 要注意 |
|---|---|---|
| **BW 端点** | 接本地 OpenAI 兼容端点,并把它上面的模型列出来 | 连不上时不抛 —— 它把原因写在输出里,整张图照跑 |
| **BW 问题** | 问题 + 他自己说的既成事实 | facts **拼进问题里**发,不单开字段(见下) |
| **BW 起卦** | 投掷 → 排盘 → 用神 → 裁决梯 → feature → 关系 | **没有模型。** 但它在 M1 **后面** —— 用神由 `db=` 定 |
| **BW M1** | `lang / db / ask / hurt / flags / facts` | `db=` 错,整盘用神就错 |
| **BW M2** | 选库(两级 RAG 的第一级) | 「注」里写着它排到了哪几个库 |
| **BW M3** | 把盘变成这一卦的事,出词条 | 「注」里写着**开了哪几张卡** |
| **BW M4** | 解读本身 | 「注」里那行「槽:」—— 里面**没有 board** |
| **BW 看** | 把一段文字显示出来,并原样传下去 | |

每一站都有 `model` / `temperature` / `max_tokens` / `dry` / `pin`:

- **`temperature` 默认 0。** 不是 0 的时候你在调噪声,不是在调提示词。
- **`dry`** = 只建提示词、不调模型,把 system 全文打在「注」里。改完提示词先用它看槽填对没有。
- **`pin`** = 填了就直接拿这段当这一站的输出。用来试「**如果** M1 把 db 判成疾病会怎样」。

## 三件从别处搬过来、别在画布上绕过去的事

**① facts 不单开字段。** 线上没有那个字段 —— 人就是把「她是医学生」打在问题里的,
而 M1 的活正是**从他打的字里**把既成事实抄出来(`facts=` 那一行)。
单开一个字段直接喂给它,等于替它做了那一步,于是画布上**永远测不出它会不会漏抄**。
「BW 问题」的第二个输出就是 M1 实际收到的原文,拿它对一眼。

**② 用神由 M1 的 `db=` 定,所以起卦在 M1 后面。** 不接 M1,用神退回世爻 ——
**而那副盘照样能跑完四站**,四篇材料都交得出来,只是读的是另一副盘。
节点会在盘面上打一行警告;`db_旁路` 那个控件是给 `dry` 用的,**线上没有这个旁路**。

**③ M3 只看得见 M2 开的那几个库的卡。** M2 少选一个库,M3 就再也看不到那个库的卡,
**而它照样有卡可读、照样交得出材料**。M3 的「注」里列着实际开的卡号,
和 M2 的「注」里那几个库对一眼。

## 改完节点定义之后

那张 workflow JSON 是**从节点定义生成的**,不是手写的:

```bash
python3 tools/comfy/build_workflow.py          # 重新生成
python3 tools/comfy/build_workflow.py --check   # 只校验
```

手写的 JSON 是第二张要同步的名单:插口名、控件顺序、类型在 `nodes.py` 里改一个,
它就悄悄错位,而它报出来的是「widget 值对不上」这种跟原因毫无关系的话。

⚠️ **这张图没有在真的 ComfyUI 里打开过。** 校验的是结构 —— 节点类型存在、
插口名存在、每条线两头类型相同、控件值个数对得上,这几样正是手写最容易错的地方,
但它**不等于**「在 ComfyUI 里跑通了」。`tests/comfy-pack.mjs` 钉着同一批性质。

## 它不是什么

**画布是工作台,站点才是产品。** 线上跑的是 `functions/api/claude.js` 里那条路
(计费闸 → 危机闸 → `buildNode` → SSE),Comfy 这边**没有计费、没有危机闸、
没有流式、没有前端**。要整站在本地跑,那是隔壁:`npm run local`(见 `tools/lab/README.md`)。

这边调好的提示词就是线上那份 —— 因为它们是同一个文件。
