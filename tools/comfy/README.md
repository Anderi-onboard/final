# BourneWise · ComfyUI

两条管线,各一张图,一站一个节点,连线就是管线。**改一站的提示词,只有那一站和它下游重跑。**

| 图 | 是什么 |
|---|---|
| `workflows/bournewise-puzzle.json` | **解谜管线(实验中,owner 定的新架构)**:读问题 → 程序出题 → 每条线索一个模型 → 验现事 → 解谜 |
| `workflows/bournewise-puzzle-dry.json` | 同一张图,一个模型都不用下:M1 钉住一段示范答案,后面每一站只建提示词 |
| `workflows/bournewise-4node.json` | 线上那条:M1 → M2 → M3 → M4 |
| `workflows/bournewise-4node-dry.json` | 同一张图,只建提示词 |

## Windows + Unsloth + Qwen3.8(owner 的用法)

**① 起模型。** Unsloth 起的是 OpenAI 兼容端点(底下是 llama-server)。在 PowerShell 里:

```powershell
unsloth run --model unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_XL -p 8888 --disable-tools `
  --chat-template-kwargs "{\"reasoning_effort\":\"none\"}"
```

- `-p 8888`:端口。「BW 端点」默认填的就是 `http://127.0.0.1:8888/v1`。
- `--disable-tools`:不让服务端自己去搜网页、跑代码 —— 解读只许用盘和他说的话。
- `reasoning_effort`:Qwen3.8 的思考开关(`none` / `low` / `medium` / `xhigh`)。线索、验现事、M1
  都是短活,开着思考只会慢、还容易被 `max_tokens` 截在思考里。想在画布上逐站调,
  「BW 端点」的「思考」一栏可以按请求改;选「不发」就按这里启动时的设定。
- **API key 是必填的**:Unsloth 的 Settings → API 里生成 `sk-unsloth-…`(只显示一次),
  填进「BW 端点」的 api_key。

**② 装节点(软链,不要复制)。** 要 node ≥ 18 在 PATH 上(`winget install OpenJS.NodeJS.LTS`)。

```powershell
New-Item -ItemType Junction -Path "C:\ComfyUI\custom_nodes\bournewise" -Target "$HOME\bournewise\tools\comfy"
```

路径换成你自己的 ComfyUI 和仓库位置。重启 ComfyUI,节点在 `BourneWise` 和 `BourneWise/解谜` 两个分类下。

**③ 开图。** 把 `workflows\bournewise-puzzle.json` 拖进画布,「BW 端点」填 api_key,
「BW 问题」填问题,点运行。**模型名全部留空** —— 留空就用端点上列出的第一个模型,
Unsloth 一次只挂一个。

## 解谜管线

```
端点 ┐
问题 ┼─→ M1 读问题 ─→ 出题(无模型)─┬─→ 线索(逐条跑)─────┐
     │                              ├─→ 验现事(逐条跑)───┤
     │                              └────────────────────┴─→ 解谜 ─→ 解读
```

| 节点 | 做什么 | 要注意 |
|---|---|---|
| **BW 解谜 M1 读问题** | 拆成几问(`q1=` `q2=`)、每问的 db 和 kind,事实标六亲和属于哪一问 | 一卦多问要拆;`facts=我在投简历[父母\|q2]` 只落到第二问 |
| **BW 解谜 出题(无模型)** | 起卦、排盘、36 条判据、裁决梯、应期、出题 | 「题面」就是 SOP 那几步程序各做了什么;`date` 留空就是现在 |
| **BW 解谜 线索(逐条跑)** | 每条成立的判据一个模型,只写一句 | **一条一条跑**,进度条走一格一条;`pin` 用 `[q1.3]` 钉住某几条 |
| **BW 解谜 验现事(逐条跑)** | 三合、三会成局这种说「现在」的地方,拿他的原话对照 | 只答对上 / 对不上 / 他没说;说对上必须**原样抄出他的话**,程序逐字核 |
| **BW 解谜 解谜** | 拼、补细节、斟酌文字、用他的语言写 | 「材料」输出就是它看到的全部;定死的不许翻 |

⭐ **为什么线索和验现事是一条一条跑。** 它们在架构上是并联的 —— 每一条只看得到自己那一条,
互相不知道 —— 但本地一张卡同时只跑得动一个模型,并发发过去也只是在服务端排队、更容易超时。
所以节点按顺序一条一条调,每一条还是一次独立的调用。

⭐ **验现事为什么要抄原话。** 它的用处是让读的人当场核对「这一卦对上了我现在的处境」——
而一个永远「对上」的验现事就是算命先生的开场白。所以它**得能输**:模型只能答三样,
说「对上」「对不上」要把他的那一句原样抄出来,抄不出来程序按「他没说」算。

⚠️ **Qwen3.8 的思考会被剥掉。** 写在 `<think>…</think>` 里的东西不进下游 —— 思考里也会出现
`q1=`、`这一卦里=`,不剥的话下游按行解析,读到的是它想过又否掉的那一版。

⚠️ **书在建库。** 出题那一步的缓存键包括补全包里的每一份数据,往里加一条判据,下一次运行
出题会重跑,不会拿缓存里的旧题给你。

# 四站 · ComfyUI

一站一个节点,连线就是管线。**改一站的提示词,只有那一站和它下游重跑。**

```
端点 ┐
问题 ┼─→ M1 读问题 ─→ 起卦(无模型) ─┬─→ M2 选库 ─→ M3 取证 ─→ M4 解读
     │        db=                    │      ↑          ↑           ↑
     └────────────────────────────────┴──────┴──────────┴───────────┘
```

## 装法一:打一个自带依赖的包(不需要这个仓库)

```bash
npm run pack      # → dist/bournewise-comfy-<构建标签>.zip,约 170KB,要 node 在 PATH 上

# Windows 一次下完的那一版:把官方 node.exe 放进包里,解开就能用
node tools/comfy/pack.mjs --node node-v24.21.0-win-x64/node.exe --node-sums SHASUMS256.txt
                  # → dist/bournewise-comfy-<构建标签>-win-x64.zip,约 34MB
```

⚠️ `--node-sums` 给的是 nodejs.org 那份 `SHASUMS256.txt`(里面本来就有 `win-x64/node.exe` 一行),
打包时逐字节对,对不上就不打。包的顶层还有一个 `example_workflows/`,ComfyUI 的「浏览模板」会列出它。

解开,把 `bournewise-comfy` 整个文件夹放进 `ComfyUI/custom_nodes/`,完事。
包里带着引擎、提示词、RAG、两张图和假端点 —— **没有 npm 依赖,没有 Python 依赖**,
只要 node ≥18 在 PATH 上。

⭐ **它是构建产物,不是分叉。** `repo/` 底下每个文件都和仓库里**字节完全一致**
(为此包把仓库的目录结构原样放进 `repo/`,于是每一行 import 和 `parents[2]`
都自动落对,一行都不用改写);文件清单是**顺着 import 算出来的**,不是写死的;
`MANIFEST.json` 记着源提交和每个文件的 sha256。
`tests/comfy-pack.mjs` 把包铺到系统临时目录里**真跑一次** —— 少带一个文件时
`pack.mjs` 和 `nodes.py` 都一声不吭,**只有用户那台机器会炸**,所以这件事
必须跑过才算数。

## 装法二:软链(在仓库里开发时用)

**软链,不要复制:**

```bash
ln -s /你的路径/final/tools/comfy ~/ComfyUI/custom_nodes/bournewise
```

复制一份进 `custom_nodes` 就是又一张要同步的名单:盘和提示词还在仓库里改,
Comfy 上跑的是你复制过去的那一天的版本 —— **两边都不会报错。**
真要复制,就给 ComfyUI 设 `BOURNEWISE_ROOT=/你的路径/final`。

要 **node ≥ 18** 在 PATH 上(盘和提示词都在 JS 那边)。ComfyUI 看不见 node 的话设
`BW_NODE_BIN=/绝对路径/node`。除此之外**没有任何 Python 依赖** —— 只用标准库。

起 ComfyUI,把 `workflows/bournewise-4node.json` 拖进画布,填三样:
端点地址、每一站的模型名、问题。

## 为什么是 Comfy 而不是 `tools/lab/run.mjs`

`run.mjs` 的核心用法是**钉住上游**:

```bash
node tools/lab/run.mjs --only m3 --from runs/最新那个.json
```

不钉住,你分不清"这次答得不一样"是因为提示词改了,还是因为 M1 这次答得不一样。
**Comfy 的执行缓存天生在做这件事** —— 改 `prompts.js` 里 M3 那一段、存盘、再跑,
只有 M3 和它下游重跑,M1/M2 和盘原封不动。**不需要记得钉,也就不会忘了钉。**

⭐ 每一站的提示词**分别取哈希**(`IS_CHANGED`),所以改 M4 不牵动 M1。
哈希算的是:这一站在 `prompts.js` 里的那一段 + `fill.js`(填槽和 VOICE)+
M2/M3 再加上检索表。**切不出那一段时回落到整份文件** —— 宁可多重跑几站,
也不能少重跑一站:那会让你对着**上一版提示词的答案**调这一版。

## 节点

| | 做什么 | 要注意 |
|---|---|---|
| **BW 端点** | 接本地 OpenAI 兼容端点,并把它上面的模型列出来 | 连不上时不抛 —— 它把原因写在输出里,整张图照跑。「思考」一栏见上面 Qwen3.8 那节 |
| **BW 问题** | 问题 + 他自己说的既成事实 | facts **拼进问题里**发,不单开字段(见下) |
| **BW 起卦** | 投掷 → 排盘 → 用神 → 裁决梯 → feature → 关系 | **没有模型。** 但它在 M1 **后面** —— 用神由 `db=` 定 |
| **BW 四张表** | 把盘摊成 CSV:爻 / 边 / 钟 / 盘 | **没有模型。** 见下面「查地址,不是搜相似」 |
| **BW 判据** | 《增删卜易》36 条,逐条判 | **没有模型,而且不下结论** —— 见下 |
| **BW M1** | `lang / db / ask / hurt / flags / facts` | `db=` 错,整盘用神就错 |
| **BW M2** | 选库(两级 RAG 的第一级) | 「注」里写着它排到了哪几个库 |
| **BW M3** | 把盘变成这一卦的事,出词条 | 「注」里写着**开了哪几张卡** |
| **BW M4** | 解读本身 | 「注」里那行「槽:」—— 里面**没有 board** |
| **BW 看** | 把一段文字显示出来,并原样传下去 | |

每一站都有 `model` / `temperature` / `max_tokens` / `dry` / `pin`:

- **`temperature` 默认 0。** 不是 0 的时候你在调噪声,不是在调提示词。
- **`dry`** = 只建提示词、不调模型,把 system 全文打在「注」里。改完提示词先用它看槽填对没有。
- **`pin`** = 填了就直接拿这段当这一站的输出。用来试「**如果** M1 把 db 判成疾病会怎样」。

## 四张表与判据

### 为什么分四张表

爻是点,爻与爻之间的关系是边,两者行数不同。六爻恒为 6 行;
关系有 15 种配对,还带方向和成立与否。边放进 6 行的点表,丢的正好是
判据要读的方向和成立与否。

| 表 | 一行是什么 | 行数 |
|---|---|---|
| lines | 一爻 | 恒 6 |
| edges | 一条爻与爻之间的关系 | 十几条 |
| clock | 一爻对日辰、月建、太岁、时辰的一条关系 | 几十条 |
| board | 整副盘 | 恒 1 |

判据按地址取值:角色定行,格定列。元神旺相读的是 lines 表中角色为元神
那一行的旺衰格。所以输出能说出依据在第几爻的哪一格,而不只是成立二字。

### 它不下结论

200 副盘实测,忌神能克与忌神不能克同时成立的有 60 副。撞得最多的一对:

    能克一   忌神旺相，或遇日月动爻生扶，或临日月者，一也。
    不能克一 忌神休囚不动，动而休囚被日月动爻克者，一也。

忌神休囚又不动，后者成立;同时日辰生它，前者也成立。原书这两条有先后,
得日辰生就不算休囚不动。但该先后在转写成 46 条时未带过来,任何字段里都没有。
所以这一步只报条目和依据,轻重交给 M4。

### 三条要知道的

判据只读四张表,读不到盘。表够不够用,只有在求值器除表以外什么都看不见时
才证明得了。`tests/criteria-engine.mjs` 钉这一条:改一格 CSV,结论必须跟着变。

判据逐爻判,不是整盘判。输出说的是第 5 爻是进神,不是这盘有进神。
第一版对主体的几行取任一,于是第 5 爻旺而化旺、第 6 爻休而化休时,
动旺相而化旺相与动休囚而化休囚同时成立,两个条件落在不同的爻上,
而原书说的是一爻。此时 CSV 和条数都正常,看不出问题。

36 条里 9 条今天判不了,报的是判不了,不是不成立:长生十二宫不在本仓库 4 条、
化散原文未给判法 2 条、随鬼入墓未给判法 2 条、近事属问题不属卦盘 1 条。
把判不了当成不成立,会得到一个看起来正常的相反结论。

### 还没做

判据的结果没有进 M3 的提示词。M3 需要加一个 `{{criteria}}` 槽才吃得到,
那要改 `prompts.js`,也就是改产品本身。

## 三件从别处搬过来、别在画布上绕过去的事

**① facts 不单开字段。** 线上没有那个字段 —— 人就是把「她是医学生」打在问题里的,
而 M1 的活正是**从他打的字里**把既成事实抄出来(`facts=` 那一行)。
单开一个字段直接喂给它,等于替它做了那一步,于是画布上**永远测不出它会不会漏抄**。
「BW 问题」的第二个输出就是 M1 实际收到的原文,拿它对一眼。

**② 用神由 M1 的 `db=` 定,所以起卦在 M1 后面。** 不接 M1,用神退回世爻 ——
**而那副盘照样能跑完四站**,四篇材料都交得出来,只是读的是另一副盘。
节点会在盘面上打一行警告;`db_旁路` 那个控件是给 `dry` 用的,**线上没有这个旁路**。

**③ M3 只看得见 M2 开的那几个库的卡。** M2 少选一个库,M3 就再也看不到那个库的卡,
**而它照样有卡可读、照样交得出材料**。M3 的「注」里列着实际开的卡号,
和 M2 的「注」里那几个库对一眼。

## 改完节点定义之后

那张 workflow JSON 是**从节点定义生成的**,不是手写的:

```bash
python3 tools/comfy/build_workflow.py          # 重新生成
python3 tools/comfy/build_workflow.py --check   # 只校验
```

手写的 JSON 是第二张要同步的名单:插口名、控件顺序、类型在 `nodes.py` 里改一个,
它就悄悄错位,而它报出来的是「widget 值对不上」这种跟原因毫无关系的话。

⚠️ **这张图没有在真的 ComfyUI 里打开过。** 校验的是结构 —— 节点类型存在、
插口名存在、每条线两头类型相同、控件值个数对得上,这几样正是手写最容易错的地方,
但它**不等于**「在 ComfyUI 里跑通了」。`tests/comfy-pack.mjs` 钉着同一批性质。

## 它不是什么

**画布是工作台,站点才是产品。** 线上跑的是 `functions/api/claude.js` 里那条路
(计费闸 → 危机闸 → `buildNode` → SSE),Comfy 这边**没有计费、没有危机闸、
没有流式、没有前端**。要整站在本地跑,那是隔壁:`npm run local`(见 `tools/lab/README.md`)。

这边调好的提示词就是线上那份 —— 因为它们是同一个文件。
