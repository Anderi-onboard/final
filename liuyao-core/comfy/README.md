# 看卦 工作流 · ComfyUI 版

把六爻流水线放进 ComfyUI 画布，每一站一个节点。每个节点直接显示：

- **模型节点**（理解、断法、综合）：系统提示、用户输入、模型原始输出、程序判定（合格 / 不合格、为什么）；
- **程序节点**（起卦、排盘·用神、检索）：程序判定了什么、依据哪一章。

流水线逻辑只有一份，在 `src/pipeline/`。ComfyUI 只是外壳：节点通过 `bridge.mjs` 调用同一组阶段函数。

## 安装

1. 本机装 Node.js 22（或 18+），并确认 `node -v` 能用。
2. 把 `comfyui-liuyao/` 整个目录复制到 `ComfyUI/custom_nodes/`。
3. 启动 ComfyUI 之前设置环境变量，指向本仓库的 `liuyao-core` 目录：

       export LIUYAO_CORE=/绝对路径/liuyao-core

4. 要用真模型，再设置 `OPENROUTER_API_KEY`。不设则只能跑演示模式。
5. 启动 ComfyUI，把 `liuyao-reading.json` 拖进画布，或用菜单 Load 打开。

## 节点

| 节点 | 做什么 | 输入 | 显示 |
|---|---|---|---|
| 六爻 · 配置 | mode：mock（演示）或 openrouter；三个模型名 | — | 当前配置 |
| 六爻 1 · 起卦 | 问题、六爻（0 交 1 单 2 拆 3 重，由初至上；留空随机）、日期 | 问题 | 起卦结果、本卦、变卦 |
| 六爻 2 · 理解问题 | 模型读问题，输出 JSON；程序检查格式，不合格重问一次 | 配置 | 提示词、输入、输出、判定、理解结果 |
| 六爻 3 · 用神与排盘 | 程序按对象定用神，写盘面文字，列检索标记 | — | 用神及依据、盘面文字、标记 |
| 六爻 4 · 检索 | 程序逐字匹配书中原文条目 | — | 命中原文、标记覆盖 |
| 六爻 5 · 依书断法 | 每条命中条目调用一次模型；程序丢弃引用未给出条目、爻位越界的断语 | 配置 | 每次调用的提示词与输出，采用与丢弃的理由 |
| 六爻 6 · 综合 | 模型核对、写回答；程序整理置信与未答部分 | 配置 | 提示词、输出、回答 |

## 演示模式与真模型

- `mock`（默认）：不联网，模型是**占位**，输出标有“（演示）”。只用来看连线和每站显示什么，不是解读。
- `openrouter`：真调用。三个模型名填 OpenRouter 上的 `provider/model`；没有 key 或模型名为空时，节点直接报错，不会悄悄退回演示。

## 出错时

- 某站停了（危机、需要追问、模型两次输出不合格）：这一站显示原因，后面的节点显示“上一站停止，本站未运行”。
- 节点报红：读报错文字。常见的是 `LIUYAO_CORE` 没设，或 `node` 不在 PATH 里。
