# 知识库设计：两大部分

> 状态：方案，待确认。尚未录入任何条目。

## 总览

知识库分两部分，各管一件事：

| 部分 | 回答什么 | 怎么被选中 | 例子 |
|---|---|---|---|
| **A. 名词释义** | 这个名词在占断里“是什么”“象征什么” | 按**用户意图**自由抽调 | 父母：长辈、宅舍、文书、车舟 |
| **B. 名词关系** | 名词与名词之间“怎么相处”“意味着什么” | 按**盘中实际存在的名词与状态**匹配 | 兄弟 克 妻财 → 劫财 |

两部分之间用**名词 id** 相连。状态（旺、相、死、有力、临……）本身也是名词，定义在 A 部分，计算在程序里，判断交给模型。

## A. 名词释义库

### A1 名词分类

- **六亲**：父母、兄弟、子孙、妻财、官鬼
- **位**：世、应、用神、元神、忌神、仇神、动爻、变爻、日辰、月建、卦宫、本卦、变卦
- **状态**：旺、相、休、囚、死；动、静；空（旬空）、破（月破、日破）；长生、帝旺、墓、绝；伏、飞；进神、退神；有力、无力；……
- **关系词**：生、克、比和、冲、合、刑、害、临、回头生、回头克、入墓……

### A2 每个名词的结构

```
id:        父母
kind:      六亲
definition: 书中原文定义（逐字，带出处）
meanings:  - { 占的事: 天地/城池/宅舍/文书/章奏…, 象: 长辈、房屋、文书…, source: 用神章 }
intents:   [宅舍, 文书, 长辈, 功名(部分)…]   ← 按意图抽调用
computed:  false            ← 或 true，表示程序会算它的状态
```

**例（用神章原文，行 431 附近）**：
> 父母爻：占父母，即以卦中之父母爻为用神。…占天地、城池、墙垣、宅舍、屋宇、舟车、衣服、雨具、绸缎、布匹、杂货、及章奏、文书、文章、书馆、文契，亦以父母爻为用神。

→ 条目 `父母` 的 meanings 可以拆成：占父母／占宅舍／占文书／占舟车 等，每项带 `intents`。

### A3 状态名词：知识库与程序同时写

状态要在两处同步写，并由测试守着：

1. **知识库**：`states.json` 里写定义、书中出处、适用的判断依据。
2. **程序**：每个状态有一个计算函数，输出时带上**依据**（evidence）。
   例：`旺` 的依据 = “月建为春，木旺（月令寅卯）”。

模型拿到的是 `{ 状态: 旺, 依据: 月建寅属木 }`，它可以判断，也可以质疑。程序不替模型下结论。

**例（四时旺相章原文，行 882 附近）**：
> 正月建寅，寅木旺，卯木次之；… 正、二月，木旺生火，火为相，其余金、水、土，俱作休囚。

→ 状态 `旺`、`相`、`休囚` 的定义取自这里；程序按月建计算，依据写明“月建 X 属 Y 行”。

## B. 名词关系库

### B1 关系条目的结构

```
id:          rel-xiong-ke-caicai-01
subjects:    [兄弟]                    ← 名词 id
relation:    克                        ← 关系词
objects:     [妻财]
when:                                  ← 盘中需要满足的状态（可选）
  - 兄弟 · 动
polarity:    凶 | 吉 | 中 | 视情况
meaning:     劫财之神，占财之最忌          ← 白话含义（我写，你审）
source:      { book: 增删卜易, chapter: 求财章, line: 11083, text_zh: 兄弟乃劫财之神，占财之最忌也。 }
disputed:    false
```

**例（求财章原文，行 11083 附近）**：
> 兄弟乃劫财之神，占财之最忌也。

→ 条目 `兄弟 克 妻财`：meaning = 劫财；polarity = 凶。

### B2 状态关系（也是关系）

状态之间的关系同样进 B 部分，例如：

- `用神 · 旺` 且 `元神 · 动` → 吉（依书中元神有力的五条，见元神忌神衰旺章）
- `用神 · 空` 且 `日辰 冲 用神` → 冲空即起（旬空章：冲空即起 / 冲合即开）

### B3 检索方式

- **A 部分**：由 M1（问题理解）输出的意图，选出相关名词，连同它们的 meanings 一起交给模型。
- **B 部分**：程序把盘中的名词与状态列成事实表，逐条检查每个关系的 `subjects / objects / when` 是否满足，满足的全部列出。
- 模型拿到的 = **A 的释义 + 盘中的状态（带依据）+ B 的关系**，由它把三者连起来判断。

## C. 同步与测试（守住这份设计）

1. 每个 `id` 只定义一次。B 部分引用的名词，必须在 A 部分存在。
2. 每个状态名词，必须有程序函数（或明确标注“仅模型判断”）。
3. 每条 `source.text_zh` 必须逐字在源文本中找到。
4. 每条关系的 `when` 只能使用 A 部分已定义的状态。
5. 释义的 `intents` 只能使用意图词表里的词。

4. **白话的 meaning**：我起草，你审。
