# 规则审计：原文成套列举 vs 代码判定

原文里常见“有 N 种情形：一也、二也……”的成套列举。每一套都需要：
(a) 每种机制在代码里算得出来；(b) 有判定规则说明它怎样影响结论；(c) 有出处。

## 检查方法

每补一套，先写出它的每个分支（机制 + 判定），再写独立于代码的期望（像 `void-mechanism.mjs` 那样），
最后让测试对比代码。没有独立期望的判定，不算补上。
