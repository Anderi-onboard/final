# 断法代码分区

每条断法一个 id。**id 一旦发出去就不改** —— 它是原文、代码、提示词、契约四处之间唯一的连线。
下一个人拿着 id 能在四个地方找到同一条规则,不用读注释猜。

## id 怎么编

```
SOP-<步>.<组>.<序>      通用断法(《增删卜易》六步)
DOM-<领域>.<正反>.<序>   领域断法
YH-<序>                  野鹤老人四大机制
```

领域代号:`EXAM` 考试 · `WEALTH` 求财 · `ILL` 疾病 · `MARRY` 婚姻 · `TRAVEL` 出行 · `HOUSE` 家宅

## 每条要在四个地方留同一个 id

| 在哪 | 长什么样 |
|---|---|
| 原文条目 | `{ "id": "SOP-3.忌神.不能克.7", "原文": "忌神与元神同动(贪生忘克)" }` |
| 引擎/裁决梯 | `// SOP-3.忌神.不能克.7` 写在实现它的那几行上面 |
| 提示词 | 不出现 id —— 提示词只收原文,id 是程序侧的地址 |
| 契约 | `assert(...)` 的失败信息里带 id |

⚠️ **提示词里不写 id。** 模型读的是原文,不是编号;把编号塞给它,它会开始引用编号,而读解读的人不知道 `SOP-3.忌神.不能克.7` 是什么。

## 状态怎么标

```
✅ 实现   代码里有,而且有契约钉着
🟡 半实现 代码里有一部分,或者有代码没契约
❌ 没有   一行都没有
📖 数据   不是代码,是原文条目(等打标)
```

# 结论

**能正常运行**:能。裁决梯每卦都在跑,32 条契约全绿,今天刚把关系和神煞接进包。

**全面吗**:不全面。**SOP-3 和 SOP-5 是两个大洞** ——
一个决定「这条生克到底成不成立」,一个决定「什么时候应验」。
两个洞加起来 41 条,实现 2 条。

**现在的提示词能不能补上这两个洞**:不能。这两步都是**查表**,不是判断 ——
让模型每卦自己推「元神休囚化退神所以不能生」,就是那副断错的盘的死法。
它们该进代码,不该进提示词。
